## 1. 评测目的与不做的事

**要回答的问题**：在同一个评测集上，改动某一处（换解析策略、加重试、接经验库、加图校验）之后，
抽取质量是变好还是变坏，变了多少。

**要支持的对比**（后面每个模块的 A/B 都复用这套指标）：

- 改造前 vs 改造后（稳定性、截断）
- 纯 workflow vs workflow + ReAct
- 无注入 vs 向量 Top-K vs 向量 + 元数据过滤（vs 再加图检索）
- 规则库加 / 不加

**不做的事**：

- 不评界面、不评前端交互
- 不把 token 成本当主指标（成本只作为报表附属列）
- 不评「推理说明」「来源文本片段」这类过程性字段（它们进闭环阶段的经验库，不进本阶段指标）
- 不评自由描述的措辞好坏（产物形态只做宽松命中，单独成列）

## 3. 字段口径

完全以 `eval/schema.yaml` 为准，关键约定摘录如下（详细定义看该文件）：

- 缺失一律归一为 `null`；gold 的 `空 / — / null / 00` 与模型的 `00` 等价
- **数值列的 `00` 判为缺失**（盐浓度 0、比表面积 0 都不是合法观测值）
- 组装方式、介孔结构必须先归一到大类再比，不能直接字符串相等
- 表面活性剂走同义词典（P123 = Pluronic P123 = EO20PO70EO20）
- 温度不做字符串比，只比正则抽出的温度值集合
- 结构化字段只读 `数值 / 单位 / 样品 / 原文`，多余键忽略

## 4. 记录对齐规则

### 4.1 前提修正

《实施方案》与产物契约把「样品编号」当作对齐主键，但**实测 gold 没有样品编号列**，
gold 的记录身份是隐式的（论文内的第 N 条）。因此对齐不能依赖样品编号。

### 4.2 双口径对齐（两套都报，避免对齐算法污染结论）

**口径 A：值对齐（主口径）**

1. 同一篇论文内，gold 记录 × 模型记录 两两算相似分：
   `比表面积 ±5% 命中 +2`、`孔径 ±10% 命中 +2`、`表面活性剂实体命中 +1`、`温度集合有交集 +1`
2. 贪心取最大分匹配，一条 gold 记录最多配一条模型记录
3. 相似分 < 2 判为 `unmatched`，进单独的桶——**既不算漏抽也不算多抽**
4. 值匹配跑完后，剩下的 gold 与预测**按出现顺序兜底配对**（`order_fallback` 计数单独报）。
   值匹配的作用是处理「顺序不一致」，不是「分不开就判未匹配」；数量对不上的部分才算 `unmatched`
5. 平票时按记录顺序配对

**口径 B：顺序对齐（对照）**

论文内按出现顺序一一对应。若模型记录数与 gold 不等，多出的记为 `extra`，少的记为 `miss`。

两套口径的分差本身就是信号：差得大说明模型记录切分粒度与 gold 不一致（例如把多行表当一个样品）。

### 4.3 记录归属

- 续行记录（首列为空）归属到上一条带编号的记录所属论文
- 注释行不产生记录，只把 `note` 挂到上一条记录

## 5. 指标定义

### 5.1 字段级

只在**已对齐的记录对**上计算。逐字段判：

| 情形 | 计入 |
| --- | --- |
| gold 有值、模型有值、归一后相等（数值按容差） | TP |
| gold 有值、模型缺失 | FN（漏抽） |
| gold 缺失、模型有值 | FP（多抽） |
| 两边都有值但不等 | FP + FN（抽错） |
| 两边都缺失 | TN，**排除出 P/R/F1 分母** |

- `precision = TP / (TP + FP)`，`recall = TP / (TP + FN)`，`F1 = 2PR/(P+R)`
- `normalized accuracy = TP /（有 gold 值的记录数）`，与 F1 并列报，不互相替代
- **覆盖率（必须报）**：`该字段有 gold 值的记录数 / 已对齐记录数`。
  比表面积、孔径的 gold 有值率只有约 79% / 72%，不报覆盖率会把「没抽出来」误读成「抽错了」
- 双方一致缺失率单独成列（`TN / 已对齐记录数`），用来观察模型过度填 `00` 的倾向

### 5.2 记录级

- **记录匹配率** = 对齐上的 gold 记录数 / gold 记录总数（口径 A 下 `unmatched` 计入分母）
- **表格行召回** = 来自表格的 gold 记录中被抽出的比例。
  仅对 `parse_report.json` 标出样例行且能定位到表的记录计算；定位不到的表不进该指标的分母
- 多记录论文单独汇总，用于观察「表格逐行拆分」是否真的生效

### 5.3 数值字段

- 容差：比表面积 `max(5%, 5 m2/g)`、孔径 `max(10%, 0.2 nm)`、温度 `±5 °C`、浓度 `±5%`（仅同基准）
- `>1000`、`≈1000`、`ca. 3`、`平均5.9` 这类值取数值并标记 `approx`，
  `approx` 记录的正确率单独成列，避免与精确值混算

### 5.4 分层报告

每个指标都要出三组分层：

1. **是否含表**（有 / 无）——由 `parse_report.json` 判定，这是主分层
2. **记录数**（单记录 / 多记录）——观察多记录论文的拆分能力
3. **文献类型**（软模板 / 复合 / 硬模板）——**必须人工对 20 篇子集打标**。
   不能拿模型 route 输出的「分析类型」当分层依据：那是被评对象自己产出的标签，用它分层等于自己给自己评分

## 6. 报表结构

`eval/report.md`，每次评测覆盖写。头部固定写清：

```
schema_version / prompt_version / model / parser_version
评测集版本（子集 or 全量 + 论文编号清单 + golden.jsonl 的 sha256）
运行命令 / 运行时间 / temperature
```

正文四张表：

1. **per-field**：字段 × (P, R, F1, normalized accuracy, 覆盖率, TP, FP, FN, 一致缺失率)
2. **per-paper**：论文 × (gold 记录数, 对齐数, 字段级 F1, 表格行召回)
3. **overall**：总计 + 口径 A / 口径 B 两行
4. **分层**：含表/无表、单记录/多记录、文献类型三组交叉

表后附**混淆样例 top-N**：每类错误（漏抽 / 多抽 / 抽错）各取若干条，
带 `paper_id + 记录序号 + 字段名 + gold 值 + 模型值 + 原文定位`。

---

## 7. 复现要求

- 调用侧 `temperature=0`
- 报表头部必须记 `prompt_version`（阶段三的 `core/prompt_version.py` 产出）与 `parser_version`
- 评测集固定为文件 + sha256，不用「最近一次跑的结果」
- `golden.jsonl` 入库（体积小），`predictions.jsonl` 不入库
- 验收标准：同一条命令连跑两次，`report.md` 字节一致

## 8. 已知局限

1. **gold 只有 264 条（评测分母 261 条）、分布不均**（52 篇只有 1 条记录）→ 分层报告 + 20 篇固定子集迭代，
   全量结果在例会上必须同时给出样本量
2. **gold 无样品编号、无文献类型标注** → 对齐用值匹配（口径 A），分层靠人工打标 20 篇
3. **可评样本偏少**：比表面积仅 209 条有值、孔径 190 条有值；结构化字段覆盖率仅约 56%
4. **单位基准不统一**（w% / wt% / mol/L / g 混用）→ 浓度类字段目前只能做宽松比，
   分数偏低不代表抽取差，需要在报表里注明
5. **表格是 gold 的主要来源**，而当前 markdown 里表格为 0 → 阶段一完成前的分数是「故障基线」，
   只能用来证明表格丢失的代价，不能当能力上限
6. **对齐算法本身有误差**（值匹配可能错配）→ 用口径 A/B 双报 + `unmatched` 单列来暴露，
   不对齐的样本不参与字段级指标

## 附录 C：gold 清洗实现时必须一并产出「尺子的自检」
